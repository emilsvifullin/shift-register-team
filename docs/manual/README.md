# Инструкция администратора

PDF-инструкция по Shift Register со скриншотами. Скриншоты снимаются с
настоящего приложения на демонстрационных данных, поэтому после изменений
в интерфейсе инструкцию нужно пересобрать.

## Пересборка

```sh
npm ci
npm install --no-save --package-lock=false @playwright/test@1.63.0
npm run manual -- ~/Desktop/Инструкция.pdf
```

Локальный сервер поднимается сам. Если уже запущен `npm run serve`,
используется он. В сеть ничего не уходит: Supabase подменяется заглушкой
из `e2e/support/supabase-stub.mjs`.

Команды по отдельности:

| Команда | Что делает |
| --- | --- |
| `node docs/manual/capture.mjs [шаблон]` | Снимки в `out/shots/`, можно только сцены, подходящие под шаблон имени |
| `node docs/manual/build.mjs [путь.pdf]` | `out/manual.html`, проверки и PDF |
| `node docs/manual/preview.mjs [3,7,12]` | Страницы картинками в `out/preview/` |

## Файлы

- `demo-seed.mjs` — демонстрационные данные: пункты, сотрудники, смены.
- `stand.mjs` — окно браузера и запуск приложения с этими данными.
- `capture.mjs` — сцены: что открыть, как обрезать кадр, что отметить.
- `build.mjs` — страницы, тексты и вёрстка.

## Как устроены снимки

Кадр задаётся по элементам: `el`, `from`, `until`, `margin`. Отсюда два
правила: край никогда не режет строку посередине, а если в интерфейсе
поменяется высота блока, кадр подстроится сам. Панели и диалоги
(`isolate`) снимаются без фона, а у самой панели на время съёмки сняты
углы, рамка и тень: кадр не выходит за её границы.

Поэтому все снимки в документе одного вида: прямоугольник с одним
скруглением (3 мм) и одной тонкой рамкой, которые даёт `build.mjs`.
Исключение одно — экран телефона: его углы повторяют скругление
устройства. Подложек, теней, растворённых краёв и CSS-масок нет: Chrome
записывает такие эффекты в PDF полупрозрачными картинками, и Просмотр на
macOS рисует их серыми прямоугольниками. Проверять готовый PDF стоит в
Просмотре, а не только в браузере.

Номера и рамки на картинку не рисуются. `capture.mjs` сохраняет их
положение в `out/shots/<имя>.json`, а `build.mjs` накладывает поверх
снимка. Поэтому номер на любой странице одного размера, как в пояснениях.
Если на снимке отмечать нечего, пояснения идут списком без номеров.

Если отмеченный элемент не найден или вышел за кадр, сцена падает с
понятной ошибкой. Обычно это значит, что в интерфейсе переименовали
класс или кнопку.

`build.mjs` проверяет, что ни одна страница не переполнена, что у каждой
ссылки `{{ключ}}` есть страница и что текст на снимках не мельче 4,5 pt.

## Ссылки на страницы

В текстах пишите `{{ключ}}` вместо «с. 12». Ключ — поле `key` у страницы.
Номер подставится сам, поэтому страницы можно добавлять и переставлять.
